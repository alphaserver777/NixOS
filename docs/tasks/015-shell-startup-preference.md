# Восстановление выбранной панели после входа

Состояние: заменена задачей 016.

Пользователь окончательно выбрал DMS и потребовал убрать остальные
варианты. В задаче 016 переключатель полностью удаляется, DMS запускается
напрямую службой графического сеанса. Исправление выбора отдельно не
применяется; локальное восстановление DMS и проверки причины выполнены.

Прочитаны WORKFLOW, constitution, architecture, devplan, PROCESS,
DEPLOYMENT и задача 012. Пользователь сообщает о повторном появлении
Hyprpanel после перезагрузки и просит восстановить выбранное оформление.
Локальная проверка продолжает ранее разрешённое применение на x-disk.
Общие изменения предназначены для рабочих столов; другие машины не
применяются. Канал, ядро, данные и настройки приложений не меняются.

## Причина

Загружено поколение 279 NixOS 26.05, в сеансе применено 280 того же канала.
Журнал предыдущего входа подтверждает: DMS запустился, но проверка панели
не завершилась за 20 секунд. cosmic-shell сам остановил DMS и включил
Hyprpanel. restore/activate сохранили original в shell-selection, поэтому
следующий вход сразу запустил старую панель. Это не откат NixOS.
Аналогичная короткая проверка уже отмечена в задаче 012.

## Изменение

Отделить выбранную пользователем панель (shell-selection) от временно
запущенной панели (файл в XDG_RUNTIME_DIR). Сохранять пользовательский
выбор только при явном успешном переключении. Возврат при ошибке не
перезаписывает его; следующий вход повторяет запуск выбранной панели.
Ожидание готовности увеличить до 90 секунд; службе выбора дать 120 секунд.
Продолжать проверять ответ панели, а не только запущенный процесс.
В текущем сеансе восстановить DMS без закрытия приложений.

## Проверка

- [x] Задержанный ответ панели не приводит к преждевременной остановке.
- [x] Ошибка запуска и восстановление сохраняют предпочтение пользователя.
- [x] Явный переход на старую панель сохраняет original и допускает её запуск.
- [ ] Повторный запуск выбранного оформления отвечает, DMS активен,
  Hyprpanel неактивен, ошибки Hyprland отсутствуют.
- [ ] Сборка и применение успешны; код и документы сохранены в main.

Проверки переходов выполнять с подменёнными вызовами systemd, отдельными
каталогами состояния и искусственным временем. Они не переключают
настоящий рабочий стол. Настоящую проверку выполнять только для DMS.
Не перезагружать и не выходить из пользовательского сеанса автоматически.

Возврат: предыдущее поколение 280, путь и прежние значения состояния
сохранены в ~/.local/state/nixos-shell-startup. Сборка с одним заданием
и одним ядром, в фоне. Настройки DMS и плагины сохраняются.

Пять автоматических проверок test-shell-switch.py прошли. Временное
состояние, ответы служб и время подменены: задержанный ответ через 35
секунд принимается; неудачный resume сохраняет dms, временно разрешая
Hyprpanel; явный original сохраняется; restore не меняет предпочтение;
новый сеанс запрещает запуск старой панели при выбранном dms.

Текущий сеанс восстановлен через новую версию shell-switch.py из
репозитория, без изменения конфигурационных файлов вручную. Служба
nixos-shell-startup-recover завершилась успешно за 38,6 секунды.
Панель отвечает visible, центр управления возвращает состояние,
cosmic-dms активен, Hyprpanel неактивен; выбор и текущая панель — dms.
Календарь, hypridle и rclone активны; ошибок Hyprland нет.

Сборка идёт в фоне, nixos-shell-startup-build.service; материалы:
~/.local/state/nixos-shell-startup/build.status и build.log.
Следующий шаг: проверить её завершение, применить собранную систему
из чистого зафиксированного состояния без остановки DMS, проверить
TimeoutStartSec=120 и повторный resume. Только после этого завершить
задачу и объединить изменения в main. Другие машины не применять.
