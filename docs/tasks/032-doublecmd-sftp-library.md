# Библиотека SSH для SFTP и SCP в Double Commander

Состояние: выполнено. Дата: 23 октября 2026 года.

Прочитаны WORKFLOW, constitution, architecture, devplan, PROCESS,
DEPLOYMENT, задачи 010, 011 и 031. Изучена официальная документация
Double Commander о библиотеке libssh2 для модуля FTP.

## Причина и цель

Установленный Double Commander 1.2.9 из закреплённого nixpkgs-unstable
содержит ftp.wfx, но не предоставляет libssh2.so.1. На выборе SFTP/SCP
появляется «LibSSH2 library not found». Добавить библиотеку в область
поиска Double Commander для всех штатных способов его запуска.

## Область и решение

Добавить локальную упаковку Double Commander: использовать готовую
программу, дать ей LD_LIBRARY_PATH с libssh2 из того же набора пакетов.
Исходную программу заново не компилировать, версии и flake.lock не менять.
В file-manager.nix использовать этот пакет в home.packages, ярлыке и
службе открытия файлов. Не добавлять библиотеку в общее окружение.

Настройки серверов и ключи не читать и не изменять. Другие машины
не применять. Локальная проверка текущей рабочей машины — по запросу
пользователя, как в задачах 010/011; перед применением сохранить текущее
поколение, зафиксировать исходники и просмотреть план применения.
Открытую программу принудительно не завершать: передача файлов может идти.

## Проверка

- [x] До исправления libssh2.so.1 недоступна обычному загрузчику.
- [x] Новый пакет собирается, библиотека загружается и инициализируется.
- [x] Все три способа запуска используют исправленный пакет; конфигурации
  Huawei, main и x-disk вычисляются.
- [x] Исправление применено локально, обработчик папок и службы работают.
- [x] Ограничения проверки и способ повторного подключения записаны.
- [x] Пользователь подтвердил подключение к своему серверу после полного
  закрытия и повторного запуска Double Commander.

Доступ к удалённому серверу проверить после устранения ошибки библиотеки;
конкретный сервер и способ авторизации пользователь пока не указал.
Загрузка библиотеки не является подтверждением авторизации на сервере.

## Возврат

Сохранить путь текущей системы и настройки Double Commander в закрытом
каталоге ~/.local/state/doublecmd-sftp-20261023. Для возврата применить
предыдущее поколение. Личные настройки подключений сохраняются.
Длительную сборку запускать в фоне одним заданием и одним ядром.

Источник: https://doublecmd.github.io/doc/en/plugins.html#ftp.

## Применение и результат

Сборка пакета и системы завершилась с кодом 0. До исправления обычный
загрузчик возвращал cannot open shared object file для libssh2.so.1.
Проверочный Double Commander запущен отдельно с QT_QPA_PLATFORM=offscreen,
собственным каталогом настроек и отдельным именем экземпляра. В окружении
реального исполняемого файла присутствует новый LD_LIBRARY_PATH. В этом
окружении ctypes загрузил libssh2.so.1, libssh2_init(0) вернул 0,
версия библиотеки — 1.11.1. Проверочный экземпляр закрыт отдельно;
пользовательский экземпляр принудительно не завершался.

Вычисления Huawei, main и x-disk прошли: ярлык и служба используют один
пакет. Применено поколение 285, система:
/nix/store/yml71pfgn3gfyxmhyrs12r9i0p2vbp1p-nixos-system-x-disk-26.05.20261006.b253099.
Предыдущее поколение 284 сохранено. План требовал только перезапуска
Home Manager; путь ядра до и после одинаков. В установленном окружении
doublecmd и doublecmd.desktop указывают на исправленный пакет,
inode/directory обрабатывает doublecmd.desktop. Служба FileManager1
активна с новым запуском, NRestarts=0; DMS активна, отказов пользовательских
служб нет, режим запрета простоя сохранился выключенным.

Для уже открытого экземпляра изменение области поиска библиотек не
применяется. Пользователю предложено полностью закрыть Double Commander,
запустить через Win + E и повторить подключение. Пользователь подтвердил:
«Да, подключился». Подключение и авторизация на сервере подтверждены;
отдельная передача файлов не проверялась.
Материалы проверки: ~/.local/state/doublecmd-sftp-20261023.
