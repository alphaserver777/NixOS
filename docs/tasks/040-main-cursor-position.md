# Проверка смещения указателя на main

Состояние: выполняется. Дата: 2026-10-25.

Контекст WORKFLOW, constitution, architecture, devplan, PROCESS,
DEPLOYMENT и задачи 034, 035, 037 прочитан; изменений правил относительно
предыдущих задач нет. Работа в fix/main-display-clarity, основа b4ff6ea.

## Проблема и факты

Пользователь видит указатель ниже и правее точки щелчка. На присланном
снимке — проверочная страница с зелёной точкой и красным указателем.
Задан вопрос: симптом во всех приложениях или только в браузере;
ответ пока не поступил. Утверждать причину по одному снимку нельзя.

Hyprland 0.55.4, nouveau/TU116. Все три экрана: масштаб 1, поворот 0,
cursor.zoom_factor=1, hotspot_padding=0. cursor.no_hardware_cursors=2
(исходное значение), hardwareCursorsInUse=true на всех экранах.
Активное окно Chrome работает через Wayland. Тема DMZ-Black, размер 24;
left_ptr/default/arrow имеют активную точку (7,4) внутри изображения
24×24. Это не доказывает визуального совпадения точки на физическом
экране, но не указывает на выход за границы файла темы.

## Решение и границы

Проверить гипотезу о неверном положении аппаратного курсора:
cursor.no_hardware_cursors=1 только на main. Отдельный модуль
home-manager/modules/hyprland/cursor.nix с lib.mkIf и подключением
из общего набора Hyprland сохранит одинаковое поведение встроенного
и отдельного Home Manager для main. Другие машины сохраняют настройку
по умолчанию. Не переносить обходной путь на все видеокарты без проверки.

Сначала задать параметр работающему сеансу, затем закрепить проверенный
способ отрисовки. Не менять координаты ввода, ускорение мыши, драйвер,
тему курсора, режимы/масштабы экранов, настройки Chrome и страницы.
Не задавать искусственное смещение X/Y. Программный курсор может
изменить нагрузку и задержку отрисовки; субъективный результат нужно
подтвердить пользователю, а не объявлять устранённым по смене параметра.

## Проверка

- [x] Сохранить исходное значение, геометрию и состояние курсора.
- [x] На main параметр становится 1; hardwareCursorsInUse=false для
      всех трёх экранов; геометрия экранов не меняется.
- [x] Другие домашние конфигурации не получают параметр main.
- [ ] Сборка и установка main успешны, ядро/драйвер и план проверены;
      графический сеанс не прерывается.
- [ ] Пользователь подтвердил совпадение указателя и щелчка в обычных
      программах и на проверочной странице. Если нет — проверить
      оформление курсора самой страницы и её масштаб, сохранив
      чёткое разделение гипотезы и установленной причины.

## Применение и возврат

Журналы и предыдущее поколение: ~/.local/state/main-cursor-position-20261025.
Быстрый возврат проверки: hyprctl keyword cursor:no_hardware_cursors 2.
Постоянный возврат: отмена модуля и новое применение. Не использовать
перезагрузку настроек как возврат после установки: она вернёт записанное
значение 1. Не завершать пользовательские приложения или сеанс.
Долгую сборку оставить отдельной службе; повторная проверка через 3–5 минут.

## Источники

[Hyprland: параметры курсора](https://wiki.hypr.land/Configuring/Basics/Variables/).
Локальный hyprctl подтверждает доступность целочисленной настройки
в установленной версии; старые WLR_NO_HARDWARE_CURSORS не использовать.

## Ход выполнения

3bfe168 содержит отдельный модуль. В работающем сеансе параметр задан
как 1, все три экрана показывают hardwareCursorsInUse=false, геометрия
точно совпала с сохранённой. Реальные homeConfigurations всех шести
машин вычислены: значение присутствует только у admsys@main, у остальных
поле отсутствует. Результат: host-cursors.json в каталоге задачи.

Сборка и применение выполняются службой nixos-main-cursor-position.service.
После установки проверяются режимы, способ вывода курсора, панель и
ошибки конфигурации. Проверка глазами и ответ о программах с симптомом
остаются необходимыми; причиной смещения аппаратный курсор пока не
объявляется доказанно. Ответ пользователя может потребовать возврата
проверки и дальнейшего исследования страницы или конкретной программы.
