# Задача 050: единая космическая тема и спокойные уведомления

## Контекст и статус

В работе: оформление применено и проверено в текущем сеансе; требуется
закрепить запуск в новом поколении системы. 2026-11-13 пользователь выбрал
единую тему и улучшение уведомлений.
Прочитаны WORKFLOW.md, constitution.md, architecture.md, devplan.md,
DEPLOYMENT.md, PROCESS.md, задачи 016/029/049 и текущие исходники DMS 1.6.2.

## Цель и границы

Согласовать поверхности и акценты DMS с существующей Catppuccin Mocha
в приложениях, Hyprland, экранах входа и блокировки. Сохранить космонавта,
непрозрачность, расположение виджетов, шрифты часов, анимации и историю.
Уведомления: справа сверху на активном экране, короткий показ с индикатором
времени, тихий звук. Во время запущенного интервала Sands «Работа»
обычные уведомления остаются в истории, срочные проходят. Пауза, конец
или удаление интервала снимают это ограничение. Ручной режим «Не беспокоить»
сохраняется независимо. Заставка загрузки только обсуждается.

## Реализация

Готовый механизм пользовательских тем DMS, JSON палитры и одноразовое
обновление выбранных настроек с резервной копией. Новые установки получают
те же значения. Исходники DMS изменяются проверяемым отдельным сценарием:
тихий звук только уведомлений, ограничение показа по состоянию Sands.
Таймер и системная громкость не меняются. Проверки структуры исходников
должны останавливать сборку при несовместимом обновлении DMS.

## Применение и возврат

Применять из зафиксированного изменения. Предварительно сохранить в
закрытом каталоге ~/.local/state/cosmic-appearance-050 текущие настройки,
состояние запрета простоя и предыдущую службу. Проверить сборку Huawei
без удалённого применения; локально заменить только созданные Home Manager
файл темы и службу DMS, запустить штатную миграцию ExecStartPre и перезапустить
только панель. Ссылка на прежнюю службу позволяет восстановить запуск;
резервная копия настроек — палитру и уведомления. Полное обновление системы,
удаление поколений и перезагрузка не нужны. Постоянные исходники находятся
в Home Manager; ограниченное применение его файлов не меняет остальные
пакеты и пользовательские службы. Сохранить запрет простоя после перезапуска.

## Результат проверки

Проверка JSON и синтаксиса Python успешна. В изолированном каталоге
миграция сохранила дополнительный параметр и размещение панели, повторный
запуск сохранил последующий ручной выбор темы; резервная копия имеет права 600.
Проверяемые замены совместимы с закреплёнными исходниками DMS.
Для Huawei/main/x-disk вычислены одинаковые путь запуска и файл темы.
Собраны четыре небольшие производные (оболочка, исходники QML, миграция,
служба) и файл темы. Системная конфигурация не переключалась.

Применён результат коммита 7509c75. Служба активна, NRestarts=0.
Новый каталог QML включает идентификатор исходников оболочки и Sands,
поэтому сохраняемые данные QML обновляются при изменении любого из них.
Штатные команды cosmic-dms, включая старые сочетания клавиш, работают.
Диагностика показывает primary=#cba6f7, surface=#1e1e2e; оформление панели
проверено снимком bar.png. barConfigs и plugin_settings.json после
миграции совпали с исходными, запрет простоя остался включённым.

Проверочные уведомления отправлялись с запретом звука, закрывались по
своим идентификаторам. Обычное показывается без фокуса, скрыто при «Работе»;
срочное проходит. Пауза снимает ограничение, продолжение возвращает.
Включённый вручную DND сохранился после удаления рабочего таймера;
после проверки исходное состояние DND восстановлено. Проверен естественный
конец двухсекундного интервала: фокус снят, срочное уведомление и сигнал
таймера появились. Проверочные таймеры остановлены; начальное и конечное
состояние — No timer. История уведомлений и буфера не очищалась.
Ошибок TypeError, ReferenceError, SyntaxError, Cannot assign и циклов
привязок в журнале после запуска нет; hyprctl configerrors пуст.
Остались штатные предупреждения об отсутствующих Wi-Fi, Bluetooth,
PowerProfiles и поддержке отдельных протоколов композитора.

Проверочные материалы: ~/.local/state/cosmic-appearance-050.
Заставка загрузки, ядро, драйверы, lock/login и зависимости не изменены:
их существующая палитра уже соответствует выбранным цветам.

## Закрепление после перезагрузки

Обнаружено, что home-manager-admsys.service при каждой загрузке запускает
активацию из текущего системного поколения. Поэтому ограниченное
применение пользовательской службы само по себе не гарантирует сохранение
её нового пути после загрузки. Для постоянного результата необходимо
собрать новое системное поколение из зафиксированного изменения.
Предварительная проверка и сборка сохраняют данные в том же закрытом
каталоге. Долгую сборку выполнять отдельной службой, по одному заданию
и ядру; не ждать в чате. Перед применением сравнить ядро, модули, параметры
загрузки и состав изменений с текущей системой. Старое поколение сохранить.
Применение не должно запускать перезагрузку.
