# Доступ Double Commander к службе ключей SSH

Состояние: выполняется. Дата: 24 октября 2026 года.

Прочитаны WORKFLOW, constitution, architecture, devplan, PROCESS,
DEPLOYMENT, задачи 010, 030, 031 и 032.

## Причина и цель

Модуль SFTP сообщает SSH ERROR no auth sock variable. Пользовательская
ssh-agent.service работает, сокет существует, ключ уже загружен.
В окружении пользовательского systemd SSH_AUTH_SOCK отсутствует;
оболочка терминала добавляет его сама. Настройка OpenSSH из задачи 030
не используется библиотекой libssh2 модуля SFTP.

## Область и решение

Дополнить существующую упаковку packages/doublecmd.nix: если адрес
агента не передан, а сокет $XDG_RUNTIME_DIR/ssh-agent существует,
установить SSH_AUTH_SOCK только для Double Commander. При отсутствии
XDG_RUNTIME_DIR использовать /run/user/$UID/ssh-agent.
Непустой переданный адрес, включая перенаправленный агент, сохранять.
При отсутствии сокета переменную не устанавливать.

Не перезапускать агента, не менять ключи, их пароли, серверы, глобальное
окружение или личные настройки программы. Сохранить доступ к libssh2.
Общий пакет используется основными способами запуска на рабочих машинах;
применение выполнять только на main. Открытые окна не завершать.

## Проверка

- [x] Пакет собирается без перекомпиляции Double Commander.
- [x] Реальный процесс получает сокет при пустой и отсутствующей переменной.
- [x] Переданный адрес сохраняется; без сокета адрес не выдумывается.
- [x] libssh2 из окружения процесса подключается к агенту и видит ключ.
- [ ] Изменение применено на main; сохранены агент и его PID, проверены
      основные способы запуска и записано ограничение проверки сервера.

Проверочные процессы запускать без окна с отдельными настройками
и отдельным именем экземпляра. Читать только необходимые переменные
процесса. Удалённую авторизацию не объявлять проверенной без соединения
с указанным пользователем сервером.

## Применение и возврат

Зафиксировать исходники до применения. Сохранить текущую систему,
собрать новое поколение одним заданием и одним ядром, проверить план,
ядро и драйвер. Долгую сборку оставить в отдельной службе с журналом.
Возврат: sudo nixos-rebuild switch --rollback. Личные подключения
сохраняются. Уже открытый Double Commander потребуется полностью
закрыть и открыть заново после применения.

## Ход работы

Проверены пять запусков реального Double Commander: переменная отсутствует,
пуста, передана явно, сокета нет, XDG_RUNTIME_DIR отсутствует.
В каждом случае использовались отдельные настройки и имя экземпляра,
QT_QPA_PLATFORM=offscreen. Сохранён LD_LIBRARY_PATH с libssh2.
Через эту библиотеку успешно выполнены agent_connect, list_identities
и get_identity. Подключения к удалённому серверу эти проверки не делают.
Материалы: ~/.local/state/doublecmd-agent-20261024.
