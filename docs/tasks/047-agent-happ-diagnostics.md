# Задача 047: доступ к agent.professorit.ru через Happ

## Контекст и статус

Диагностика выполнена, 2026-10-28. Постоянное изменение правил Happ
не применялось. Продолжение задач 044/045.
Пользователь разрешил проверку dev1-robots и проброс через SSH.
Изучены рабочий процесс, конституция, архитектура и процесс задач.

## Наблюдения

Happ работает, но основная вкладка приложения остаётся пустой.
Проверка только страницы авторизации возвращает 401 и не доказывает
загрузку интерфейса. Сервер не перегружен. Внутри dev1-robots HTML
и файлы приложения отдаются за миллисекунды. В журнале Happ домен
выбирает direct, в Clash он шёл через сервер Германии. На прямых
соединениях Xray к сайту наблюдаются повторные передачи и задержки
подтверждения более двух минут.

Через SSH подняты локальные порты 13085 (Nginx без Traefik) и 13089
(SOCKS). В отдельном проверочном профиле Chrome обычный адрес сайта
через SSH и Traefik загрузил интерфейс и ресурсы, пользователь это
подтвердил. Это ещё не исключает отличие профиля/кэша старого браузера.

## План и область изменения

Проверить кэш без очистки. Для разделения сетевого пути и профиля
временно направить HTTPS к этому IP через SSH в существующем браузере.
Допустимы только отдельная диагностическая таблица nftables и локальные
SSH-пробросы; основные правила межсетевого экрана не изменять.
Существующие соединения браузера к проверяемому IP можно обновить для
повторного подключения. Данные сайта, историю, пароли и кэш не удалять.
Сервер проверять только чтением; не перезапускать приложения и Traefik.

## Результаты

- На dev1-robots нагрузка около 1–2, свободно около 48 ГиБ доступной
  памяти, корневой раздел занят на 7%. Контейнеры приложения и прокси работают.
- Авторизованная проверка с сервера: HTML 35187 байт и четыре основных
  файла интерфейса отдаются за 1–3 мс. Секрет входа использован только
  внутри серверного процесса проверки, в вывод не помещался.
- В отдельном профиле Chrome через SSH и обычный HTTPS/Traefik загружены
  HTML, JavaScript и стили, наблюдаются запросы к API. Пользователь подтвердил
  загрузку этой вкладки.
- В основном профиле обнаружены актуальные имена файлов приложения в
  кэше. Кэш, cookies, данные сайта и история не очищались.
- У прямых соединений Xray к сайту зафиксированы повторные передачи,
  окно cwnd=1, ожидание подтверждений свыше двух минут. Запросы в журнале
  Happ направлялись `tun-in -> direct`; в журнале Clash тот же домен шёл
  через сервер Германии.
- Для проверки основного профиля использован локальный SSH-порт 19443
  до серверного 127.0.0.1:443 и отдельная таблица codex_agent_diag,
  перенаправляющая только TCP/443 указанного IP от UID 1000. Соединения
  браузера к этому адресу обновлены, сайт открыт в прежнем профиле.
  Сначала пользователь сообщил о пустой странице, позднее снимок того же
  основного окна подтвердил полный интерфейс и открытый чат. Содержимое
  чата не публикуется. Это указывает на влияние сетевого пути; исключать
  все возможные ошибки состояния вкладки по одному опыту нельзя.
- Таблица удалена автоматическим ограничителем через 10 минут,
  завершение службы очистки проверено (код 0). Основные правила firewall
  и конфигурация сервера не изменялись.
- SSH master продолжает работать по запросу пользователя для тестовых
  вкладок (порты 13085, 13089, 19443); его сокет указан ниже.

Настройка приложения/подписки Happ, выбирающая direct для этого домена,
остаётся прежней. Для постоянного результата требуется отдельное явное
правило через proxy и проверка новой конфигурации без SSH-обхода.

## Возврат

Удалить только диагностическую таблицу `codex_agent_diag`.
Остановить только созданный SSH master по сокету
`~/.local/state/happ-site-20261028/ssh-control.sock`.
Проверочный профиль находится в закрытом каталоге этой же проверки.
Секреты и содержимое чатов в документацию и вывод не помещать.
