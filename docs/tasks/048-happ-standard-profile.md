# Задача 048: личный профиль Happ из стандартной подписки

## Контекст

Продолжение задачи 047. Пользователь попросил проверить возможность
локальной настройки, имея только подписку без доступа к VPN-серверу.
Изучены WORKFLOW, constitution, architecture, devplan, PROCESS,
DEPLOYMENT и задачи 044/045/047.

## Статус

В работе.

## Наблюдения и решение

Официальная документация Happ ограничивает ручную маршрутизацию готовых
JSON-подписок. Проверена уже настроенная подписка пользователя:
при запросе с User-Agent v2rayN она возвращает 14 стандартных ссылок
подключения в Base64. Параметры адреса Германии совпадают с текущим
профилем Happ. Использовать одну стандартную ссылку как отдельный личный
сервер в Happ, к которому не прилагаются прежние правила direct.

## Область работы

Только локальное приложение Happ и закрытые файлы проверки.
Исходную подписку и её правила не менять. Ключи, URL подписки и
ссылки подключения не выводить и не коммитить. Сервер провайдера
не меняется. Личный профиль — снимок параметров: его автоматическое
обновление из исходной подписки не предполагается.
Соединение пользователь включает вручную, затем проверяется сайт
без SSH-перенаправления и фактический выход proxy в журнале Xray.

## Проверка

- [x] Подписка доступна в стандартном формате.
- [ ] Личный профиль добавлен, исходная подписка сохранена.
- [ ] Пользователь включил профиль и подтвердил открытие сайта.
- [ ] Проверен маршрут через proxy без диагностического SSH-обхода.

## Возврат

Удалить только добавленный личный сервер из Happ.
Вернуться к исходной подписке; её параметры не менялись.
Закрытые материалы находятся в ~/.local/state/happ-site-20261028/.
