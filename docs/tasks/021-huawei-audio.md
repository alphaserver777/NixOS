# Huawei BOD-WXX9: HDMI и встроенный звук

Состояние: in progress. Дата: 11 октября 2026 года.

Прочитаны WORKFLOW, constitution, architecture, devplan, PROCESS,
DEPLOYMENT, TEMPLATE и задача 017.

## Контекст и цель

После перехода Huawei с 6.18.2-zen2 на 7.2.9-zen1 HDMI через SOF
возвращает STREAM_PCM_PARAMS IPC -5. Перезапуск PipeWire убирает ошибку
старта, но hw_ptr остаётся неподвижным. LG TV обнаружен, ELD корректен.
Временный HDA-режим передаёт звук; пользователь подтвердил его наличие.
Этот режим лишает ноутбук встроенного звука и микрофона.

При переинициализации SOF обнаружен второй дефект: sof_es8336_remove
освобождает gpio_speakers, но оставляет gpio_headphone занятым.
Повторная регистрация платы завершается EBUSY. Ошибочные ветви probe
тоже не освобождают все полученные GPIO.

Цель: постоянная конфигурация только Huawei с полноценным SOF-звуком,
поддерживаемой веткой ядра и корректным освобождением GPIO.
Работу HDMI, динамиков, микрофона и восстановления после сна требуется
проверить на новом ядре; успех сборки этой проверкой не является.

## Изменения и ограничения

- Вынести настройки звука Huawei в hosts/Huawei/audio.nix.
- Выбрать для Huawei ветку linuxPackages_6_18 LTS; остальные хосты
  сохраняют свои ядра. Регрессия 7.2 предполагается по журналам,
  её устранение требует проверки после перезагрузки.
- Явно выбрать SOF (dsp_driver=3) и сохранить quirk=160 для ES8336.
- Собрать только модуль snd_soc_sof_es8336 с исправлением GPIO
  из исходников выбранного ядра. Поместить его в updates/, проверить
  выбор depmod/modprobe, vermagic и присутствие в initrd.
- Сохранить прошивку, UCM, настройки маршрутизации и микшер Huawei.
- Для ALSA-узлов этой платы задавать suspend-timeout через
  monitor.alsa.rules, чтобы избегать ненужных остановок DSP.
- Текущий работающий HDA не переинициализировать. Установить новое
  поколение для следующей загрузки; перезагрузка требует сохранения
  пользовательской работы и выполняется пользователем.

## Результаты подготовки

Huawei выбирает 6.18.55; x-disk и main по-прежнему выбирают 7.2.9.
Dry-build завершился с кодом 0. Сборка получает готовое ядро и модули
из cache.nixos.org, заново компилируется только исправленный ES8336
и модуль VirtualBox для нового ядра. flake.lock и общие модули не менялись.

## Установка и проверка сборки

Код установлен из чистого commit `4f4058b` ветки `fix/huawei-audio`.
Полная сборка и `sudo nixos-rebuild boot --flake
/home/admsys/Nixos/nixos-config#Huawei` завершились с кодом 0.
Установлено поколение 142:
`/nix/store/05pj2650vhxcr91a4792vhzj51hd6ac2-nixos-system-Huawei-26.05.20261006.b253099`.
Загрузчик выбирает `nixos-generation-142.conf` с Linux 6.18.55.

`modinfo` подтверждает vermagic `6.18.55 SMP preempt mod_unload`.
`modprobe --show-depends` выбирает `updates/snd-soc-sof-es8336.ko`
и в полном дереве модулей, и в сокращённом дереве для initrd.
Журнал сборки initrd подтверждает включение этого сокращённого дерева.
Конфигурация modprobe включает `dsp_driver=3` и `quirk=160`.
Правило WirePlumber с `monitor.alsa.rules` присутствует в пакете
wireplumber-configs, подключённом через XDG_DATA_DIRS службы.

Перезагрузка не выполнена: текущая система остаётся поколением 141,
HDA продолжает воспроизводить HDMI. Аппаратные проверки выше остаются
незавершёнными до загрузки поколения 142.
